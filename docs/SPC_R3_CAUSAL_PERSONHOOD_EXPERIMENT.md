## 1. R3 question

R2 established a credible boundary for deciding **whether there is unresolved semantic work at all**.

R3 attacks the next question:

> **Why should this particular resident care, prefer, avoid, remember responsibility for, or choose one legitimate concern over another?**

The answer must increasingly come from persistent private causal state and history.

It must not come mainly from:
- a role description;
- a list of personality adjectives;
- provider improvisation;
- a free-form reason string written after the decision;
- a global designer priority score.

R3 is not a personality-prompt campaign.

## 2. Current executable gap

The current five-resident self layer is explicitly transitional:

`ResidentLifeSelfContext = { role: string, drives: string[] }`.

That prose can inform a provider, but it is not causal resident state.

The current multi-matter choice boundary is a stronger failure specimen:

- two or more legal resident matters may wait for one free body;
- `ResidentLifeChoiceOwner` truthfully freezes the candidates and rejects fabricated/stale choices;
- but it does not currently carry structured causal self state;
- the provider may select any legal candidate and provide any bounded non-empty textual reason;
- admission proves authority and freshness, not that the preference was caused by resident history.

Therefore the system can be causally safe while the resident's apparent priorities remain roleplay.

## 3. Hard boundaries

### 3.1 Causal self state != flavor text

A personhood fact must have:
- identity;
- bounded structured meaning;
- an origin in authored initial history or a factual resident/world event;
- current status;
- an inspectable effect on relevance, choice or behavior.

Free-form prose may describe this state, but cannot substitute for it.

### 3.2 Private personhood != World truth

Examples such as:
- a promise;
- an attachment;
- a preference;
- resentment;
- a remembered obligation;

belong to the resident's private state.

They are not global facts about morality or what every resident should think.

### 3.3 State != forced action

An obligation or preference may increase significance without becoming:
- an unconditional task;
- a hard-coded priority override;
- a body command;
- a guaranteed provider decision.

R3 must preserve genuine choice and conflicts between reasons.

### 3.4 No generic needs simulator by default

Do not introduce hunger/social/fun/energy bars or a large personality vector because such systems are familiar.

A state dimension must be earned by a concrete resident-life failure.

### 3.5 No resident-name policy

No core branch such as:
`if (residentId === "resident.mira") ...`.

Mira is the first pressure fixture, not architecture.

## 4. R3-A — executable characterization

Before introducing new personhood state, prove at least these current gaps.

### A. Arbitrary legal multi-matter preference

Create an identical resident/life ambiguity twice.

Demonstrate that:
- provider answer may legally choose matter B;
- the same frozen resident truth may legally choose matter C;
- each answer may justify itself only with a different free-form reason;
- current admission has no causal private preference/obligation fact that distinguishes them.

This is not an authority bug. It is a **personhood-causality gap**.

### B. Authored self prose is not causal state

Show where `role/drives` enters provider-facing context and where it does not.

Do not treat changing those strings as proof that a resident acquired a causal preference.

### C. Same evidence, different history

Build the later R3 qualification around two otherwise equivalent resident specimens receiving the same new World/private evidence.

One has a relevant persistent private history/state; one does not.

Required outcome:
- observation truth is the same;
- resident-relative significance may differ;
- the difference is attributable to the private causal state, not resident name or prompt wording.

## 5. First candidate pressure: obligation / promise

The first likely state dimension is an **obligation/promise**, because it has a naturally causal lifecycle:

`origin evidence -> open responsibility -> relevant later fact -> fulfilled/released/superseded`.

This is a candidate, not a commitment to a universal personhood schema.

It is attractive because it can falsify R3 cheaply:
- exact origin can be preserved;
- status can be explicit;
- later relevance can be matched to grounded actors/subjects;
- the same later evidence can matter differently depending on history;
- fulfilment can terminate its effect without deleting history.

If this pressure does not produce useful behavioral differentiation, replace it rather than expanding it.

## 6. First R3 vertical target

A bounded deterministic specimen should eventually prove:

1. two Mira-like residents have the same authored role/drives and same current World observation;
2. both receive the same ordinary observation through the R2 gate;
3. only one carries a relevant open causal obligation from earlier private history;
4. the R2 observation remains observation truth for both;
5. a resident-relative personhood/relevance layer promotes unresolved pressure only where the open obligation makes the fact consequential;
6. resolving/releasing the obligation removes that extra significance for later equivalent evidence;
7. no provider is required to decide whether the causal relation exists;
8. no resident-name special case is used.

The semantic provider may later judge **what to do** with the resulting conflict.
It should not invent **why the resident cared in the first place**.

## 9. Anti-cheat rules
